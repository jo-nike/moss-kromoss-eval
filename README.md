# MOSS-Image vs Kromoss

Side-by-side evaluation of three variants of the [MOSS-Image](https://github.com/OpenMOSS/MOSS-Image) architecture on
the same 300 prompts and seeds, rendered locally on an RTX 5080 (16 GB) with stock ComfyUI nodes, then graded image by
image against each prompt's own checklist.

**View the comparison: https://jo-nike.github.io/moss-kromoss-eval/**

> Status 2026-10-19: MOSS SFT and Kromoss 8-step are complete and graded. Kromoss 25-step is still rendering
> (213 of 300 on the site); sets A to D are graded.

| column | weights | steps | sampler | CFG | skip-layer guidance |
|---|---|---|---|---|---|
| MOSS SFT | [`moss_image_sft_bf16`](https://huggingface.co/Comfy-Org/MOSS-Image) | 25 | er_sde / simple | 2.5 | layer 22, 0-50% |
| Kromoss | [`kromoss_bf16`](https://huggingface.co/lodestones/Kromoss) | 25 | er_sde / simple | 2.5 | layer 22, 0-50% |
| Kromoss 8-step | `kromoss_bf16` + `8-steps-dmd-lora` at 1.0 | 8 | euler / simple | 1 | none |

Shared by all three: text encoder `qwen3.5_9b_int8_convrot` (`CLIPLoader` type `moss_image`), VAE `flux2-vae`,
negative `nsfw, worst quality, bad anatomy, watermark, jpeg artifact` (inactive at CFG 1), model shift default (5),
`EmptyFlux2LatentImage` at ~2 MP (1456x1456 square, 1936x1088 at 16:9, and so on), seed = CRC32 of the prompt id.

The MOSS and Kromoss columns differ only in the diffusion-model file. Kromoss's own card recommends 50 steps / CFG 3,
or the LoRA at 8 steps / CFG 1, and it was fine-tuned at 1024 px. The 25-step column therefore tests Kromoss as a
drop-in for the MOSS benchmark settings, not at its preferred settings.

Rendered with ComfyUI v0.41.0-18 ([`6607f36b`](https://github.com/comfyanonymous/ComfyUI/commit/6607f36b53c7b695b160ac5b52d595e9e3752a2d)),
torch 2.12.1+cu130, driver 610.57.04. The MOSS column was rendered on 2026-10-18, the Kromoss columns on 2026-10-19,
on the same ComfyUI commit.

## The prompts

Six sets of 50, each prompt written with a checklist of 4-8 things the image must show:

| set | covers |
|---|---|
| A | single people: ages, expressions, hands doing precise things, mirrors |
| B | groups and counting: 2-15 people, objects by count, physical interaction |
| C | sci-fi, fantasy, architecture, impossible geometry, scale ratios |
| D | art styles: cartoon, anime, comics, painting, print media; captions vs tags |
| E | text, graphic design, layout: English, Chinese, bilingual, 8 JSON bounding-box layouts |
| F | lighting setups, camera technique, materials, food, animals, weather |

## How the grading works

Each image was graded from a 1280 px JPEG by a Claude vision agent, one agent per set of 50, that read the prompt and
its checklist, looked at every image, graded each check pass / partial / fail, then looked past the checklist (finger
counts, faces, exact rendered text, dropped or added elements, artefacts) and gave a 1-5 score. The instructions are in
`bench/graders/`; the three models' versions differ only in the model name, its settings and the input directory.

Things to keep in mind:

- Graders never saw another model's images or grades for the set they were grading. They did read earlier sets'
  written summaries for calibration, as the original MOSS graders did; for the Kromoss columns those are the MOSS
  summaries of *other* sets, so every model's grader had the same calibration material.
- One grader per set per model, so grader-to-grader variation is not measured. Treat gaps of a tenth of a point with
  caution; the per-check notes in each strip show what drove a score.
- Grades come from a 1280 px copy. Fine banding or texture visible only at full resolution may be missed.

## Repository layout

```
index.html, data.json      the site (data.json is generated by build_data.py)
img/<model>/full/<id>.jpg  full-resolution JPEG q95 of each render
img/<model>/thumb/<id>.jpg 800 px thumbnails for the grid
bench/prompts_[A-F].jsonl  the 300 prompts with their checklists
bench/results_<model>.jsonl render log: seed, size, seconds, output file
bench/reviews/<model>/     per-image grades (review_X.jsonl) and per-set findings (review_X.md)
bench/graders/             the grading instructions as run
bench/runners/             the ComfyUI API runners and image converters
```

`<model>` is `moss`, `kromoss` or `dmd8` (Kromoss 8-step). The original PNG renders are attached to the
[releases](https://github.com/jo-nike/moss-kromoss-eval/releases), one zip per model.
